Архитектура

Botify устроен как небольшой DI-ориентированный runtime поверх Telegram.Bot.

Слои

1. Конфигурация

BotifyOptionsBuilder хранит:

  • токен бота;
  • базовый URL Telegram API;
  • символ начала команды;
  • разделитель callback-данных;
  • разделитель inline-запросов;
  • логгер и минимальный уровень логирования;
  • пользовательский HttpClientHandler;
  • обработчики неизвестных команд, callback и inline.

2. Контекст

BotifyContext создаётся на каждый входящий Update и содержит:

  • Client;
  • Update;
  • Services;
  • CancellationToken;
  • Options;
  • Logger.

Для удобства в нём есть вычисляемые свойства:

  • User;
  • Chat;
  • Message;
  • Text;
  • CallbackQuery;
  • InlineQuery.

3. Регистрация

AddBotifyHandlers() сканирует загруженные сборки и регистрирует:

  • handler-классы с атрибутами Botify;
  • валидаторы, реализующие IBotifyValidator.

4. Исполнение

BotHostedService принимает обновления и маршрутизирует их так:

  • Message → сначала payment-сценарий, затем command-handler, затем message-handler;
  • CallbackQuery → callback-handler;
  • InlineQuery → inline-handler;
  • PreCheckoutQuery → payment-handler;
  • остальные типы логируются как неподдержанные.

Контракт handler-метода

Botify не вызывает произвольные сигнатуры. Допускается только:

Task SomeHandler(BotifyContext context)

Если сигнатура другая, регистрация завершится ошибкой.

Порядок обработки сообщения

Для текстового сообщения Botify сначала пытается найти команду. Только если команда не найдена, управление переходит к message-handlers. Это важно учитывать, если у вас есть пересекающиеся regex-шаблоны и команды.
